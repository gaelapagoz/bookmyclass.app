Illustrative demo scenario

Emma wants to attend a Tuesday evening Pilates class

Emma is a fictional sample client. She already owns a five-class pack and wants to confirm her place without contacting the studio manually. The journey below uses the public demo flow and seeded-style sample data rather than a real customer story.

Scenario boundary This is a guided way to read the demo screens and the product decisions behind them, not a statement about a real customer.

Discover and choose

Public discovery gives clients enough context to make a booking decision

The studio landing page, class catalogue, class detail pages, teacher/session information, schedule, and availability help a client understand what is offered and whether a place is available.

Confirm access

Account and access checks happen before the booking is confirmed

Clients sign in or create an account, then the platform presents applicable access options: an eligible membership, a class pack, or Stripe checkout where payment is required.

Access eligibility is validated before a booking is confirmed.

Complete the booking

Confirmation connects booking status, payment handoff, and capacity

The booking summary, entitlement use or payment handoff, booking confirmation, capacity update, and booking communication are part of a single client workflow rather than separate admin chores.

Manage changes

The dashboard handles routine booking changes after confirmation

Clients can view upcoming bookings and history, manage cancellations where policy allows, join or cancel waitlist entries for collective classes, and review membership, wallet, and loyalty information.

Attend and continue

Attendance and remaining access stay visible after the booking

Supported flows include client self check-in, attendance visibility, remaining access or wallet information, loyalty visibility and reward redemption, and a path back to booking another class.

Business-rule summary

Domain rules are visible in the journey without exposing implementation detail

Capacity rule

Bookings are tied to sessions with capacity and active waitlist behavior for collective classes.

Eligibility rule

A booking must be backed by eligible access, a valid entitlement, or a reconciled payment path.

Cancellation rule

Dashboard cancellation evaluates configured policy and can restore credit where supported.

Waitlist rule

Clients can join or cancel waitlist entries; promotion is eligibility-aware for active collective classes.

Account verification rule

Protected client routes require a verified user session.
